# KEYS Family — Learning & Practice Layer

Date: 2026-09-24  
Status: **CANONICAL PRODUCT RULE**

KEYS Family keeps learning because tokenized-stock markets are complex and young users need context. The change is that learning is no longer bureaucratic permission homework.

## Principle

> **Learn in context. Act freely inside bounds. Ask for more freedom only at the boundary.**

Learning helps Maya understand what she is doing. It does not certify maturity and it does not automatically grant capital authority.

## Source-backed reality

Important investing claims must be anchored in a primary or official source whenever one is available.

For the hackathon learning path:
- stock ownership / issuance / risk / diversification use Investor.gov / SEC material;
- tokenized-security structure and holder-right distinctions use current SEC material;
- each sourced lesson shows the organization, source title, link and date checked;
- current market facts come from KEYS/Pyth only when the backend marks the evidence fresh;
- sample values remain visibly sample;
- source-backed education is not personalized investment advice.

Do not cite a source decoratively. The source must support a concrete learning claim or nuance visible to the user.

## Applied learning loop

The preferred pattern is:

`CONCEPT → REALITY CHECK → TRY IN EXPLORE/PRACTICE → BOUNDARY/RECEIPT → REFLECTION`

A lesson should move quickly from explanation to an observable product action. Practice applies the concept with no real capital. Money Mode remains governed only by the Mandate.

## Learning moments

### 1. First exposure
Before Maya uses an unfamiliar asset/action, show a short explanation of:

- what the instrument is;
- concentration/diversification;
- volatility;
- tokenized-security representation and actual holder rights;
- issuer-sponsored versus third-party representation where relevant;
- market-session / 24-7 differences where relevant.

Target: seconds, not a course.

### 2. Practice
Practice uses the same market evidence and decision vocabulary but moves no real capital.

A younger or inexperienced user can practice first. A more experienced teen may already have a small real bounded Mandate.

### 3. Boundary explanation
When an action is refused, explain the reason in human language:

- current limit;
- requested amount;
- market condition;
- what requires a boundary request.

The refusal should teach without shaming.

### 4. Market-condition learning
If Pyth invalidates a user's own precommitted condition, show:

- what was true at T0;
- what is true now;
- which condition changed;
- why the old request is no longer valid.

### 5. Review / reflection
After a meaningful action:

- what did Maya expect?
- what actually happened?
- did her stated invalidation condition trigger?
- did she follow the rule she set?

P&L remains a separate fact, not the quality score.

## Never do

- quiz score → wider authority;
- profit → wider authority;
- AI maturity score → wider authority;
- mandatory essay before every in-bounds trade;
- public on-chain diary of a minor;
- leaderboard or gamified risk-taking.

## Relationship to authority

Learning may lead to:

`Ready to ask for a Mandate review?`

It may never produce:

`Mandate automatically widened.`

Only an authorized principal can widen the human Mandate.

## Family policy pack

The familiar progression can remain as narrative:

`LEARN → PRACTICE → PROPOSE → BOUNDED → INDEPENDENT`

but the underlying authority is always the explicit Mandate permission envelope.

A teen may therefore be:

- real BOUNDED for diversified assets;
- PRACTICE-only for a new risk class;
- PROPOSE-only above a certain notional;

at the same time.

This is why stages are UX and the Mandate is truth.
